# OfferLab v0.1 → v0.2 版本对比

## 为什么选择这个问题

三名真实用户的30条标注中，P1和P2的Precision@10分别为80%和100%，但仅选择AI产品方向的P3只有20%。宏平均Precision@10为66.67%，低于预设70%门槛。P3的前10混入数据研发、软件开发和算法岗位，因此“目标方向组合没有被正确理解”是影响主任务的最高优先级问题。

## 修改前后

|维度|v0.1|v0.2|
|---|---|---|
|AI产品语义|AI与产品词分别命中，容易召回AI开发|识别AI产品、人工智能产品、智能产品和AI产品经理等组合表达|
|产品职责证据|出现普通“产品”即可避免降权|必须出现产品经理/管理/规划/设计/全生命周期、需求、用户研究或竞品证据|
|产品岗位供给|50条集团上限下易被开发、算法岗位挤出|每集团先保留最多24条明确产品岗位，再按岗位族补齐|
|展示目录|259条，产品岗位供给不足|仍为259条；明确产品岗位28条，北京7条|
|地点|仅占5%排序分|画像地点默认约束候选集，可主动切换查看全部|
|C/C++|C语言、C++、C/C++未形成完整技能链|统一识别并用于岗位优势与缺口|
|原版JD|入口位于详情抽屉底部|岗位卡直接提供原版JD入口|
|语言画像|存在但没有稳定参与判断|删除；JD语言要求继续标为人工核实|

## 已有量化证据

- v0.1三人宏平均：NDCG@10 0.9087，Precision@10 0.6667，高度相关岗位平均5个。
- P3第一次修正后：Precision@10由0.20升至0.30，但高度相关岗位为0，仍未通过。
- v0.2浏览器验证：P3画像下医疗AI产品经理、AI产品经理位列前两名；这是排序行为检查，不能替代真实相关性标签。
- 能力推断规则契约测试：10/10通过。

## v0.2复测门槛

使用与P3相同画像重新标注Top 10：

- Precision@10至少达到0.70；
- 高度相关岗位至少3个；
- 前5中开发/算法岗位不超过2个；
- 首个高度相关岗位排名不低于第2位；
- 所有原版JD入口可从岗位卡直接找到。

若Precision仍低但目录中合格产品岗位不足，应记录为候选供给问题，而不是继续放宽语义规则。

## v0.2正式复测结果

P3复测画像为统计学/应用数学、北京与上海、SQL/Python及项目证据、仅AI产品。结果为：NDCG@10 0.9481、Precision@10 0.60、高度相关岗位3个。第一、第二名均为高度相关岗位，前5中开发岗为2个。

四项门槛中，高度相关岗位数、首个高度相关排名和前5开发岗数量通过；Precision@10未达到0.70，因此v0.2未通过阶段8验收。按模型分数重建推荐顺序后的NDCG@10为0.9400；原导出文件按标注点击顺序保存，不能保证严格等于推荐顺序，该方法问题在v0.3修复。

## v0.3候选修正

- 标注JSON按当前模型排名导出，并写入 `ordering: current_model_rank`；
- 产品岗位配额由每集团24条提高到32条，并优先保留标题、公司和地点组合不重复的岗位；
- 展示目录仍为259条、每集团最多50条，明确产品岗位增至36条，北京增至12条；
- 新进入目录且与统计专业相关的北京岗位包括联通支付产品经理、办公及风险监管产品经理。

v0.3仍需第二次真人复测，不能将目录扩容直接换算成Precision提升。
