# OfferLab 产品定义 v0.3

> 历史版本：已由 `product-brief-v0.4.md` 取代，保留用于展示产品决策演进。

## 产品定位

OfferLab 是一个面向央企校招有限志愿场景的证据化资格审计与岗位比较实验。

## 一句话价值

帮助应届生在占用有限投递名额前，看清自己是否具备申请资格、哪些条件仍需核实，以及候选岗位之间真正重要的差异。

## 核心用户

第一阶段面向目标企业明确、需要在集团及下属单位之间选择有限志愿的 2027 届应届生。种子用户为统计学硕士、精算学本科，掌握 Python 和 SQL，目标地点为北京，目标企业为三大运营商和三桶油。

## 核心问题

1. 招聘信息分散在集团、子公司和不同招聘系统；
2. JD 字段不统一，专业、学历和英语要求需要逐条核验；
3. 同名岗位职责不同，不同岗位名称又可能高度相关；
4. 集团可能限制投递数量或锁定志愿，选错岗位的机会成本较高；
5. 综合匹配分无法解释硬性资格、不确定信息和个人偏好。

## MVP 模块

1. **用户资格画像**：届次、学历、专业、英语、地点、技能和偏好；
2. **岗位资格审计**：逐项输出符合、不符合或待核实，并引用原文；
3. **有限志愿比较**：在 2–3 个岗位间比较资格、职责、证据、未知项、地点、截止时间和名额规则。

## 产品原则

- 官方来源和原文证据优先；
- 硬性资格与软性相关性分开；
- unknown 是正式结果，不由 AI 猜测；
- 用户做最终决定；
- 不输出录取概率；
- 不用单一综合分掩盖资格风险；
- 第一版追求可评测的判断质量，不追求岗位数量。

## 成功标准

- 用户能正确理解三种资格状态；
- 用户能在比较页发现至少一个原先忽略的差异；
- 与手动官网流程相比，任务耗时下降或错误减少；
- 系统资格结论均能追溯至 JD 原文；
- GitHub 公开评测集、指标和失败案例；
- 完成至少一次有依据的产品迭代。
