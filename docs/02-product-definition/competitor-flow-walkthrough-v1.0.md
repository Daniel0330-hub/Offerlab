# 竞品关键流程走查 v1.0

## 目标任务

> 作为 2027 届统计学硕士，希望在北京寻找三大运营商或三桶油的产品、数据、经营分析或数字化岗位，判断自己是否具备申请资格，并比较有限志愿应该优先投哪一个。

本轮以公开页面和无需登录的流程为主。需要登录、上传简历或付费才能验证的步骤明确标记，不伪造测试结果。

## 求职喵

公开流程为岗位表筛选、查看届次和截止时间、登录后上传简历开启机会雷达，再收藏、投递或使用网申插件。它的字段直接，也覆盖央国企和自动填表；但一个招聘公告可能聚合多个岗位，细粒度专业资格仍需进入公告核验。公开流程未展示硬性资格逐项证据、有限志愿比较和简历匹配准确性。

## OfferSeek

公开流程从近 7 天岗位列表开始，可切换校招、社招或实习，按地点、企业和岗位名称筛选，查看结构化 JD、更新时间和官方入口，再保存筛选或开启雷达。它的官方来源、时效窗口和快照口径清楚；但个人资格仍需自行判断，公开流程未展示三状态资格审计、有限志愿和结构化对比。

## OfferComing

公开流程支持按公司、岗位、城市、届次、企业性质、行业和学历筛选；用户可上传简历或填写专业、学历、届次、城市和意向岗位，获得画像、相邻方向、匹配度和理由，再加入投递计划并跟踪笔面试。它与 OfferLab 原始设想高度重合。AI 选岗为会员能力，公开页无法验证匹配依据粒度、unknown 和资格申诉机制，也未看到集团有限志愿的专门支持。

## Offer派

公开流程强调浏览岗位、AI 匹配、岗位定制简历、自动网申、内推和面试建议。它直接解决重复填表和投递效率问题；但公开表达以效率和综合匹配百分比为主，判断依据、人工复核与有限志愿比较未得到验证。这一工程范围不适合三周 MVP 模仿。

## JobPal

公开流程覆盖岗位搜索、城市和学历等筛选、收藏、职业档案、简历、JOJO AI 匹配、求职记录、面试和日历；Pro 还支持批量 JD 匹配和排序。它的通用求职闭环较完整，但央企校招资格和志愿规则不是公开核心，逐条证据引用和结构化横向比较需要登录或付费后进一步验证。

## 流程结论

OfferLab 不复制“岗位库—简历上传—匹配分—自动投递”的完整链路。三周实验流程应为：

1. 导入少量可信岗位；
2. 将硬性资格逐项拆开；
3. 对每个结论引用原文；
4. 把不确定项交给用户核实；
5. 在集团有限志愿下比较 2–3 个岗位；
6. 保存用户选择理由，供后续验证。
