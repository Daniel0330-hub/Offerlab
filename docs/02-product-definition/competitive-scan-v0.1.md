# 校招岗位产品竞品扫描 v0.1

> 本文件为早期扫描。正式阶段 2 结论见 `competitor-matrix-v1.0.md`、`competitor-flow-walkthrough-v1.0.md` 和 `opportunity-map-v1.0.md`。

> 调研日期：2026-10-06。仅基于公开页面，用于界定 OfferLab 第一版产品边界。

## 市场已有能力

公开产品已经普遍覆盖以下能力：

- 多来源校招岗位聚合；
- 按届次、城市、学历、企业性质等筛选；
- 上传简历后进行 AI 匹配；
- 收藏、投递追踪或自动网申；
- 跳转企业官方投递入口；
- 岗位更新提醒。

因此，“聚合岗位 + 上传简历 + 输出匹配分”不足以构成清晰差异。

## OfferLab 的切入点

### 1. 从“搜索结果”转向“资格明确的候选集合”

系统先识别招聘类型、面向届次、学历、专业和经验门槛。无法确认时显示“资格待核实”，而不是把岗位直接标成适合。

### 2. 从“职位名称匹配”转向“实际工作内容比较”

将 JD 拆成职责主题、业务场景、能力要求和硬性门槛。用户能够看到不同公司同名岗位的职责差异，也能发现不同名称下的相似工作。

### 3. 从“黑盒推荐”转向“召回理由”

每个推荐岗位说明是由专业、课程、项目、技能、行业偏好还是用户主动目标触发。用户可以关闭不认可的召回依据。

### 4. 从“无限职位库”转向“小范围高质量验证”

MVP 只选择 10–20 家目标企业，保留原始 JD、官方链接、抓取或录入时间，重点验证资格过滤、机会召回和横向比较的价值。

## 不采用的竞争方式

- 不以岗位总量作为第一阶段优势；
- 不承诺全自动投递；
- 不用不可解释的综合匹配分作为主要界面；
- 不在缺少结果数据时预测录取概率；
- 不自动改写或虚构用户经历。
