# OfferLab 机会地图 v1.0

## 市场已充分覆盖

| 用户任务 | 竞品覆盖程度 | OfferLab 决策 |
|---|---:|---|
| 聚合大量岗位 | 高 | 只使用小规模验证数据，不竞争数量 |
| 2027 届、城市、学历筛选 | 高 | 作为基础功能实现 |
| 简历 AI 匹配 | 高 | 不以综合匹配分为卖点 |
| 同义岗位和相邻方向扩展 | 中高 | 仅保留可解释召回 |
| 收藏、投递跟踪和提醒 | 高 | 第一版只记录最终选择，不做完整 CRM |
| 自动填写网申 | 中高 | 不进入三周 MVP |
| 简历优化与面试准备 | 高 | 不进入本项目范围 |

## 值得验证的机会

### 1. 资格审计，而不是黑盒匹配分

把届次、学历、专业、英语、地点等条件分别输出为 `符合`、`不符合` 或 `待核实`，同时展示 JD 原文和用户证据。使用 20–30 条人工标注岗位评测误放、误杀和 unknown。

### 2. 有限志愿下的岗位组合决策

在比较页展示集团、招聘单位、可投名额、当前占用、截止时间、志愿锁定风险和用户选择理由。用“3 个岗位、2 个名额”的情景验证用户是否意识到机会成本。

### 3. 证据化横向比较

按硬性资格、职责主题、用户证据、信息缺口、地点偏好、官方来源和更新时间比较 2–3 个岗位。比较官网和原型完成相同任务的时间、错误与发现差异数。

### 4. 公开 AI 评测和失败案例

在 GitHub 中公开脱敏岗位样本、人工答案、指标和错误类型，展示如何判断 AI 是否可靠。这一能力主要服务于作品集可信度。

## 产品定位修订

### 新定位

**面向央企校招有限志愿场景的证据化资格审计与岗位比较实验。**

### 一句话价值

OfferLab 帮助应届生在占用有限投递名额前，看清自己是否具备申请资格、哪些条件仍需核实，以及候选岗位之间真正重要的差异。

## 差异假设

本项目不声称形成商业护城河。实验差异来自：场景更窄、资格逐项举证、unknown 正式输出、关注有限志愿机会成本，以及公开 AI 评测。
