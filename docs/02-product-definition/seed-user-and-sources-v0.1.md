## 面向种子用户的岗位族

岗位召回分为三层，避免只搜索“AI 产品经理”。

### A 层：直接相关岗位

- AI 产品经理；
- 数据产品经理；
- 产数产品/解决方案产品；
- 数字化产品运营；
- 大数据产品运营；
- 人工智能运营与应用。

### B 层：能力高度可迁移岗位

- 经营分析；
- 数据分析；
- 市场分析与市场策划；
- 用户运营、业务运营；
- 战略运营；
- 数字化转型与企业信息化；
- 项目管理与解决方案支撑。

### C 层：专业背景相关岗位

- 风险管理；
- 精算或保险相关业务；
- 财务分析、预算分析；
- 审计、内控；
- 量化分析、统计分析；
- 国际贸易和经营计划；
- 能源交易或商业分析。

C 层仅在岗位明确接受统计学、数学、精算、金融、经济或相关专业时召回，不能仅凭文本语义推断具备报名资格。

## 资格筛选顺序

系统必须先判断硬条件，再计算内容相关性：

1. 招聘类型是否为校园招聘；
2. 用户毕业届次或毕业时间是否符合；
3. 学历层次是否符合；
4. 专业是否被明确接受；
5. 是否存在外语、证书、政治面貌等条件；
6. 工作地点是否在用户接受范围；
7. 是否超过企业或招聘项目的投递数量限制；
8. 通过硬条件后，再分析职责、技能和经历相关性。

每个条件保留三种状态：`符合`、`不符合`、`信息不足`。信息不足不能自动视为符合。

### 英语条件判断规则

用户有托福 100 分，但没有 CET-4/6。系统按岗位原文分别处理：

1. 岗位没有英语硬性要求：英语条件记为 `符合/不适用`；
2. 岗位仅要求“英语能力良好”：托福 100 可作为能力证据，但保留原始成绩；
3. 岗位明确写“CET-4/6 425 分及以上”，且没有替代说明：记为 `不符合`，不能自动将托福换算为 CET；
4. 岗位写“CET-4/6 或同等英语成绩”：如未给出托福阈值，记为 `信息不足` 并提示向招聘单位核实；
5. 境外院校毕业生存在单独规则时，必须结合用户学校类型和招聘公告判断。


## 岗位比较维度

对六家企业的岗位进行横向比较时，第一版统一展示：

- 企业、招聘单位和业务板块；
- 校招批次与面向届次；
- 岗位原始名称与归一化岗位族；
- 工作地点；
- 学历和专业要求；
- 外语及其他硬性条件；
- 核心职责主题；
- 与种子用户经历相符的证据；
- 尚未被证明的能力；
- 招聘人数；
- 截止时间；
- 投递数量限制；
- 官方来源和最后核验时间。

## MVP 数据范围

第一轮不追求抓取六家企业全部岗位。建议按以下方式建立验证集：

- 每家企业选择 10–20 个候选岗位；
- 六家合计约 60–120 个岗位；
- 同时包含明显适合、边界适合、专业不符和社招误入等样本；
- 每条岗位保留原始 JD 和人工核验标签；
- 由种子用户对召回结果标注“愿意查看/不愿意查看”及原因；
- 用这批数据评估资格过滤准确性、岗位召回率和比较页面价值。

## 初版成功标准

1. 校招/社招分类不能出现严重误导；
2. 所有岗位均可追溯至官方来源；
3. 专业和届次不明确时必须提示核实；
4. 在 60–120 个岗位中，至少发现若干用户原本没有搜索但愿意考虑的岗位族；
5. 用户能在一张比较表中完成不同集团、不同下属单位岗位的初筛；
6. 与逐个浏览官网相比，找到并确认 5 个候选岗位的时间明显缩短。
