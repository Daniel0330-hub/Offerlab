# OfferLab 产品定义 v0.4

## 产品定位

OfferLab 是面向应届生的 JD 驱动岗位发现、技能匹配与横向比较实验。

## 一句话价值

OfferLab 不只按职位名称找工作，而是理解 JD 中的实际职责、软件和技能要求，发现名称不同但内容相关的岗位，再帮助用户判断能力覆盖并完成横向比较。

## 核心用户

第一阶段面向目标行业或企业大致明确，但不知道所有可投岗位名称、需要在多个相似岗位之间选择的 2027 届应届生。

## 核心问题

1. 用户需要先形成候选岗位集合，才能进一步判断和比较；
2. 招聘信息分散，岗位名称和分类方式不统一；
3. 同名岗位的实际职责可能不同，不同名称的岗位又可能高度相关；
4. 只按职位名称或关键词搜索会漏掉高关联岗位；
5. 用户需要判断 JD 中明确要求的软件、技术和业务能力是否被自己的经历覆盖；
6. 集团有限志愿使岗位选择具有机会成本。

## MVP 模块

1. **用户能力画像**：届次、学历、专业、地点、技能、软件工具、项目证据和目标方向；
2. **JD 驱动岗位发现**：综合职责语义、技能工具、专业领域和职位名称召回候选岗位；
3. **技能与资格判断**：区分硬性门槛、明确必需技能、优先技能和能力缺口；
4. **岗位横向比较**：比较职责、技能覆盖、证据、缺口、地点、截止时间和志愿规则。

## 产品原则

- 搜索是核心流程的一部分，即使它不是市场差异点；
- 职位名称只提供弱信号，不能成为唯一召回依据；
- JD 职责和明确技能是主要召回与判断信号；
- “必须/熟练/掌握”和“优先/了解/加分”需要区分；
- 用户缺少某项优先技能时不能直接判定无资格；
- 每项匹配结论保留 JD 与用户证据；
- 硬性资格、技能覆盖、岗位相关性和用户偏好分开；
- 用户完成最终选择。

## 英语处理

- 英语不作为用户核心偏好、岗位召回特征或独立匹配维度；
- 用户画像不要求填写英语成绩；
- JD 若明确提出语言证书或成绩，只作为“其他明确条件”展示；
- 第一版不进行 TOEFL、CET 等成绩换算；
- 语言条件不影响 JD 职责与技能相关性召回。
