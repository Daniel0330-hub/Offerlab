# OfferLab 项目日志

## 2026-10-05：项目选题形成

- 项目目的确定为提升中国大厂/央企 AI 产品经理岗位竞争力；
- 用户背景：统计学硕士应届生，本科精算学，主要使用 Python 和 SQL；
- 比较多个选题后，选择 AI 求职决策助手；
- 初步提出“证据优先、结果复盘、用户保留最终决定权”的产品原则。

## 2026-10-06：用户问题收敛

- 完成 8 名正在求职用户的探索性调研；
- 共同问题：企业招聘官网分散，综合招聘平台中校招与社招混杂，同名岗位要求不同；
- 用户愿意持续记录投递结果，但不会轻易因系统建议改变自己的选择；
- 产品从通用求职决策助手收敛为面向应届生的校招岗位筛选与横向比较工具。

## 2026-10-06：目标用户和企业确定

- 种子用户为 2027 届统计学硕士，本科精算学；
- 技能为 Python、SQL；
- 目标地点为北京，接受轮岗；
- 英语为 TOEFL 100，无 CET-4/6；
- 目标企业为中国移动、中国联通、中国电信、中国石油、中国石化和中国海油；
- 明确托福不能自动替代岗位硬性要求的 CET-4/6。

## 2026-10-06：首轮岗位验证

- 在中国电信北京公司 2027 校招中发现 AI 产品经理和产品经理岗位；
- 岗位学历和专业范围与种子用户匹配，其中专业明确包含统计学；
- 岗位职责包括需求调研、竞品分析、产品规划、原型、PRD、跨团队协同和迭代；
- 该发现证明 OfferLab 项目可以同时作为实际求职工具和 AI 产品经理能力证据。

## 2026-10-06：项目范围重新确认

- 明确本项目是求职作品集实验，不是商业招聘平台；
- 不追求上线、大量用户和全网岗位覆盖；
- 不做生产级爬虫、自动投递、用户账户、支付或高并发；
- 最终交付为可本地运行的 MVP、脱敏演示数据、产品文档、AI 评测、用户测试、一次迭代和 GitHub README。

## 2026-10-06：三周计划确认

- 默认投入为每周 15–20 小时，总计约 45–60 小时；
- 预算上限为 50 元；
- 岗位样本基线为 20–30 条；

## 2026-10-06：阶段 3 范围纠偏与 v1.1 修订

- 接受用户纠偏：岗位搜索虽非市场差异点，却是形成比较集的必要上游；
- MVP 主链路修订为“能力画像 → 岗位发现 → JD 匹配 → 横向比较 → 用户决定”；
- 将 JD 职责和技能设为主要召回信号，初始实验权重分别为 40% 和 35%；
- 将专业/领域和岗位名称设为辅助信号，初始实验权重分别为 15% 和 10%；
- 增加异名高相关召回与同名低相关抑制的反例验收；
- 将 Java、Python、SQL 等软件和技能纳入要求分级及覆盖判断；
- 英语不再作为核心画像、资格偏好或独立召回权重，仅在 JD 明示时作为其他条件展示；
- 更新产品定义至 v0.4、PRD 至 v1.1，并同步用户故事、信息架构、指标、验收标准、数据结构和范围冻结；
- v1.0 文档保留并标记为历史版本，以便 GitHub 展示决策演进；
- 阶段 3 修订验收通过，阶段 4 以 v1.1 为唯一执行基线。

## 2026-10-06：阶段 4 原型 v1.0 完成

- 绘制“能力画像 → 岗位发现 → 证据详情 → 横向比较 → 用户决定”的核心任务流；

- 比较页支持 2–3 个岗位并列比较和记录用户决定；
- 加入异名高相关和同名/技术词相近但职责低相关的演示反例；
- 完成 3 人测试计划和统一记录模板；
- 原型包含合成测试数据并明确标注，不作为真实招聘信息。
