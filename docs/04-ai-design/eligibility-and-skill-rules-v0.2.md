# 资格与技能判断规则 v0.2

> 当前基线：配合 PRD v1.1。规则将在阶段 5 通过金标准样本继续修订。

## 判断顺序

1. 基础资格过滤：招聘类型、届次、学历、专业、地点等；
2. JD 相关性：职责、技能、专业/领域、岗位名称；
3. 技能覆盖：把 JD 技能与用户技能证据逐项比较；
4. 其他明确条件：展示 JD 明示但不属于核心检索维度的条件；
5. 输出证据、风险和信息不足，由用户做决定。

## 基础资格状态

- `pass`：用户信息明确满足；
- `fail`：存在明确冲突；
- `unknown`：JD 或用户信息不足；
- `not_applicable`：岗位未提出此条件。

只有明确硬性条件不满足才输出 `fail`，不得把偏好、推测或常识当作硬门槛。

## 技能要求分级

| 级别 | 常见措辞 | 缺失时处理 |
|---|---|---|
| required | 必须、熟练掌握、能够独立使用 | 关键缺口，可能导致 risky/ineligible |
| expected | 掌握、具备、能够使用 | 能力缺口，通常为 risky |
| preferred | 优先、加分项 | 提示差距，不淘汰 |
| exposure | 了解、熟悉者优先 | 弱信号，不淘汰 |

同一技能在不同岗位可以有不同级别，必须依据各自 JD 原文判断。

## 技能覆盖状态

- `covered`：用户画像中有对应技能及可信证据；
- `partial`：有相邻技能或有限证据；
- `gap`：用户明确缺少该技能；
- `unknown`：用户未提供足够信息。

例如，JD 要求 Java 时不能因为用户会 Python 就判断为已覆盖；可以记录相邻编程经验，但 Java 仍为缺口或待确认。

## 英语及语言条件

- 英语不作为用户核心偏好、独立岗位召回特征或默认资格项；
- 若 JD 没有语言要求，不展示英语判断；
- 若 JD 明确要求 CET、TOEFL 或语言能力，归入“其他明确条件”并引用原文；
- 不自动换算 TOEFL 与 CET，不推断未公开的替代关系。

## 禁止行为

- 仅凭岗位名称判定相关或不相关；
- 将“优先”判成硬性不满足；
- 缺少证据时输出确定结论；
- 把检索排序值表述为录取概率；
- 用综合分隐藏关键技能缺口。
