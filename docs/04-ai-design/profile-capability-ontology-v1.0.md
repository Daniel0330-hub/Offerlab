# 用户画像能力本体 v1.0

## 目标

将专业、明确技能和项目证据转成可解释的岗位匹配信号，使同一份 JD 能针对不同用户展示不同的优势、可迁移能力和待补技能。

## 三层判断

1. **明确掌握**：用户直接填写，或项目证据明确出现的工具与技能，例如 SQL、Python、pandas、Java。
2. **可迁移能力**：由专业或上位技能推断的基础能力。例如 SQL 支持“数据查询、基础数据分析”；统计学支持“统计分析、统计建模”；人工智能专业支持“机器学习基础”。
3. **待补技能**：JD 明确要求，但画像中既无直接证据，也无合理可迁移证据的技能。

每项推断保留来源和置信度，并在画像、岗位详情和横向比较中展示。专业只推断领域基础，不能推断具体工具熟练度。例如人工智能专业不能直接判定掌握 PyTorch；大数据专业不能直接判定掌握 Spark 或 Java。

## 首版映射示例

|画像证据|推断能力|置信度|
|---|---|---|
|SQL|数据查询、基础数据分析、数据库基础|高|
|统计学/应用统计|统计分析、统计建模、数据分析|中|
|精算学|风险分析、统计建模、数据分析|中|
|大数据/数据科学专业|数据分析、数据工程基础、数据平台基础|中|
|人工智能相关专业|人工智能基础、机器学习基础、模型训练基础|中|
|用户访谈、需求分析|用户研究、需求分析、产品方案|高|

## 推荐与比较方式

- 推荐排序使用目标方向、明确技能、推断能力、项目经历、专业和地点偏好。
- 资格判断仍以 JD 原文为准；推断能力不能覆盖毕业年份、学历等硬门槛。
- 岗位详情分别显示明确优势、专业/可迁移优势和待补技能。
- 横向比较按同一三层结构展示，使用户能判断补齐成本，而非只看总分。

## 评测边界

`capability-inference-cases-v1.0.json` 检查应推断能力与禁止过度推断项。该测试验证规则实现一致性；真实推荐质量仍需用不同专业用户对岗位相关性做三级标注。
