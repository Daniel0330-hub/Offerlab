# OfferLab 探索性用户研究结论

> 状态：8 名同处求职阶段的用户探索性调研，待通过行为测试验证  
> 更新日期：2026-10-06

## 已观察到的现象

1. 求职者当前最明显的困难集中在“找到合适岗位”和“判断岗位是否适合自己”。
2. 求职者愿意持续关注并记录投递结果，说明投递追踪具备较好的行为基础。
3. 求职者不太会仅因为系统建议而改变原有判断，说明强结论式推荐的影响力有限。

## 样本补充

- 调研人数：8 人；
- 共同背景：当前正在求职，核心需求集中在应届生/校园招聘机会；
- 共同任务：先在企业招聘官网或综合招聘网站寻找岗位，再判断自身是否适配；
- 主要障碍：企业官网入口分散；综合招聘网站中校招、实习和社招混杂；相同职位名称在不同公司的职责和门槛并不一致；用户需要逐条阅读后才能判断。

本轮尚未补充每位参与者的专业、目标行业、毕业届次、求职城市和访谈方式，因此结论仍按探索性研究处理。

## 初步解释

用户缺少的不是另一个替自己做决定的评分器，而是：

- 从分散企业官网和招聘平台集中发现校招岗位的方式；
- 可靠区分校招、实习和社招的资格过滤；
- 可比较的岗位信息；
- 判断所需的证据；
- 低成本的投递记录；
- 基于自身结果形成的复盘线索。

第三项发现意味着产品不应把单一“匹配分”设计成最终答案。用户可能不理解、不信任或不接受这个分数。产品需要呈现评分依据、信息缺口和不同选择的代价，让用户保持最终决定权。

## 重新定义的问题

### 原问题

如何用 AI 判断一个岗位是否值得用户投递？

### 修订后的问题

如何帮助应届生从分散且混杂的招聘信息中，找到符合其毕业届次、专业、经历和能力的校招岗位，理解不同公司岗位之间的实际差异，并用可验证的信息完成横向比较？

## Jobs to Be Done

当我寻找校招机会时，我希望系统能够从企业官网和招聘渠道中筛出我具备申请资格、与我的专业和经历相关的岗位，将不同公司的岗位整理成可比较的机会，并告诉我每项判断依据来自哪里，从而减少反复搜索和逐条阅读 JD 的时间，但仍由我决定是否投递。

## 产品设计原则

1. **证据优先**：所有岗位判断都应引用 JD 或用户经历中的证据。
2. **比较优先**：帮助用户比较多个岗位，而非孤立地展示一个匹配分。
3. **建议可忽略**：建议不阻断操作，用户可以按自己的判断继续投递。
4. **记录低摩擦**：尽量自动生成投递记录，只要求用户补充必要状态。
5. **结论有边界**：数据不足时明确显示不确定性，不生成虚假的规律。
6. **结果驱动迭代**：长期根据用户真实投递结果调整分析，而非只依赖静态简历。

## 需要继续验证的问题

1. 用户是否需要系统主动扩展其没有想到的岗位名称和相邻职业方向？
2. 用户判断岗位时最关注哪些信息：毕业届次、专业限制、硬性门槛、工作内容、成长空间、公司质量、薪资地点，还是成功概率？
3. 用户目前如何记录投递，在哪一步最容易停止维护？
4. 用户不采纳系统建议，是因为不信任依据、不认可目标，还是已经形成明确偏好？
5. 用户更愿意比较多少个岗位：2 个、3 个，还是一个岗位列表？

## 当前研究限制

- 已知样本数量和共同求职场景，但尚未完整记录每位参与者的背景与提问方式。
- 结论可能受到熟人样本和当前求职阶段影响。
- 用户表达的意愿不等于实际使用行为，需要通过原型任务验证。
- “愿意记录投递”需要进一步确认可接受的操作成本和持续时间。
