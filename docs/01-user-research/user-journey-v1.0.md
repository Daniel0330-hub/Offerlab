# 当前校招岗位搜索用户旅程 v1.0

## 旅程概览

| 阶段 | 用户行为 | 使用渠道 | 主要判断 | 主要问题 | 机会点 |
|---|---|---|---|---|---|
| 1. 发现企业 | 从社交媒体、招聘平台、校招通知、朋友或付费聚合站了解企业 | 小红书、招聘平台、校招通知、社交网络 | 企业是否值得关注 | 用户只能看到已知企业，容易遗漏 | 扩展相邻企业和岗位方向 |
| 2. 找到招聘入口 | 搜索企业官网并进入校招专区 | 企业官网、聚合链接 | 是否为官方来源 | 入口分散，需要重复搜索 | 汇总可信官方入口与核验时间 |
| 3. 初筛岗位 | 使用地点、企业类型、名称、专业等条件筛选 | 官网筛选器、招聘平台 | 校招/社招、地点、专业、学历 | 平台可能混入不同招聘类型；筛选字段不统一 | 统一字段和硬性资格状态 |
| 4. 阅读 JD | 对照专业、项目、实习、技术栈和能力要求 | 岗位详情页 | 自己是否具备申请资格和能力 | 难以判断能力层级；“相关专业”等表述模糊 | 区分硬性资格、证据覆盖和待核实项 |
| 5. 比较岗位 | 在多个页面之间切换，比较 JD 和个人偏好 | 浏览器标签、表格、记忆 | 地点、薪资、职责、工作强度、兴趣 | 同名岗位差异大；信息缺失；缺少统一比较 | 2–3 个岗位结构化横向比较 |
| 6. 选择志愿 | 在有限岗位名额中决定投递顺序 | 企业招聘系统 | 哪个岗位最值得占用名额 | 集团存在投递数量、志愿锁定和慢反馈 | 显示投递规则、截止日期和决策理由 |
| 7. 投递与等待 | 重复填写资料并等待筛选结果 | 各企业官网 | 是否进入下一轮 | 重复填表；反馈慢；志愿可能被锁 | 当前版本记录结果，自动填表进入未来路线 |
| 8. 调整策略 | 根据是否获得面试调整后续方向 | 个人记录、记忆 | 哪类岗位更可能进入下一轮 | 结果分散，难以形成稳定结论 | 未来版本提供个人投递复盘 |

## 情绪与风险高点

1. **发现阶段**：担心遗漏未知企业和未知岗位名称；
2. **资格判断阶段**：担心误判专业、学历或能力层级；
3. **志愿选择阶段**：有限名额和慢反馈使错误选择的代价上升；
4. **等待阶段**：缺少透明反馈，难以决定是否调整策略。

## MVP 聚焦区间

本项目第一版聚焦第 2–6 阶段：官方入口、岗位初筛、JD 证据、横向比较和志愿规则。自动填表和长期复盘保留为后续方向。
