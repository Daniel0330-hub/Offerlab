# 痛点优先级 v1.0

## 评估方法

根据四份补充访谈中的出现频率、任务影响和三周 MVP 可解决程度进行定性排序。频率仅反映当前小样本，不外推为总体比例。

| 痛点 | 样本证据 | 任务影响 | MVP 可解决性 | 优先级 |
|---|---|---:|---:|---:|
| 岗位来源分散、依赖已知企业 | P1、P2、P3、P4 | 高 | 高 | P0 |
| 难以找到真正适合自己的岗位 | P1、P2、P3 | 高 | 中高 | P0 |
| JD 字段和岗位名称不统一，比较成本高 | P1、P2、P3、P4 | 高 | 高 | P0 |
| 难以判断硬性资格与能力层级 | P1、P2、P3、P4 | 高 | 中高 | P0 |
| 地点、薪酬、强度和个人偏好缺少统一比较 | P2、P3、P4 | 中高 | 中 | P0/P1 |
| 集团投递数量、志愿锁定和慢反馈 | P4 | 高 | 高 | P1 |
| 综合平台混入校招和社招 | P2；其余用户认为官网标签明确 | 中 | 高 | P1 |
| 重复填写企业申请表 | P4 | 中高 | 低 | Future |
| 缺少投递结果复盘 | P3，早期 8 人研究 | 中 | 中 | Future |

## P0：进入三周 MVP

1. 可信官方岗位样本入口；
2. 统一招聘类型、届次、学历、专业、地点和截止时间；
3. 硬性资格的 `符合/不符合/待核实`；
4. 基于用户证据的相关岗位召回；
5. 2–3 个岗位横向比较；
6. 保留原始 JD 与来源证据。

## P1：进度允许时加入

1. 集团投递数量和志愿锁定规则；
2. 用户主观偏好权重；
3. 平台来源的招聘类型复核；
4. 信息缺失清单。

## Future：不进入三周 MVP

1. 自动填写网申；
2. 全网实时抓取；
3. 薪资与工作强度社区数据库；
4. 长期投递策略学习；
5. 录取概率预测。
