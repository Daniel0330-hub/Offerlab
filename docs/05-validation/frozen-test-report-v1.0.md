# 冻结测试集最终验证报告 v1.0

## 执行规则

本轮在查看排序结果前，为11条冻结测试岗位建立20组查询：10组直接表达和10组释义改写。相关性标签只根据岗位职责、技能和资格证据确定。测试使用已经冻结的检索配置v1.1，运行后没有修改查询、标签、同义词、字段权重或融合权重。

测试脚本只允许结果文件生成一次；结果文件已经存在时会拒绝再次运行。运行清单保存配置、测试集、查询和结果的SHA-256摘要。

## 结果

| 方法 | Recall@5 | Recall@10 | NDCG@5 |
|---|---:|---:|---:|
| 原始字段匹配 | 57.50% | 57.50% | 55.47% |
| 字符TF-IDF | **100.00%** | **100.00%** | **88.40%** |
| 冻结两阶段方案 | **100.00%** | **100.00%** | 88.21% |

冻结方案在所有20组查询的前五名中均召回全部人工相关岗位，说明JD全文字符召回显著降低了只看名称或固定关键词造成的漏筛。原始字段匹配只有57.50%，证明真实用户改写会明显削弱精确词匹配。

重排NDCG@5为88.21%，略低于纯字符TF-IDF的88.40%。因此本轮证据支持“字符TF-IDF负责发现岗位”，尚不能证明当前30/70字段融合能改善未见集团上的排序质量。

## 主要误差

- “制定企业数据口径，检查数据可靠性并用脚本做分析”中，数据治理岗排在第五名。`数据口径`、`可靠性`与JD中的`数据标准`、`数据质量`仍需要更强的语义映射；
- “让多个AI代理协同完成任务并用企业知识提升回答效果”中，智能体开发岗排在第二名，产品管理岗因AI工具和业务需求表述排到前面；
- “检查航空装备是否符合质量和准入认证要求”中，军贸理工岗排在适航质量岗之前，说明共享的航空专业词压过了适航职责；
- 信息化与系统运维查询全部召回目标，但通用产品和数据岗位有时插入两个相关岗位之间。

## 产品结论

当前低成本方案已经适合演示“根据JD发现异名相关岗位”：20组冻结查询Recall@5为100%。排序分数应继续作为辅助信息，界面必须展示命中的职责、技能和资格证据，让用户自行横向比较。

当前结论受11条测试岗位、3家集团和人工查询影响，不能宣称达到生产级推荐效果。后续扩充语料时应建立新的测试版本，保留本次结果作为不可修改的基线。
