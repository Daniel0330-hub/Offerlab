# 开发集 v0.2 复核报告

> 历史快照：记录15条开发集状态。当前开发集已达到20条，见 `development-set-review-v0.3.md`。

## 当前规模

- 岗位：15 条，全部来自可回溯的官方招聘详情；
- 集团分布：中国电信 3 条、中国移动 7 条、中国联通 5 条；
- 城市：北京、合肥、南京、太原、大同、巴彦淖尔、海口、烟台；
- 岗位方向：产品、数据分析、AI 应用与研发、系统架构、网络安全、网络与算力运维、卫星网络、技术支撑、项目交付；
- 数据质量：全部通过 `scripts/validate_dataset.py`。

## 本轮新增 2 条

1. 中国联通北京市分公司——算力运维工程师；
2. 中国联通北京市分公司——卫星网络运营工程师。

两条岗位都允许统计学类专业申请，但职责方向明显不同。算力运维岗位突出操作系统、云平台、容器、巡检和故障处理；卫星网络岗位突出解决方案、用户需求转化、网络架构和通信协议。这组样本可检验系统是否会越过岗位名称，依靠 JD 内容召回相邻机会。

## 覆盖改善

- 中国移动占比从 53.8% 降至 46.7%；
- 中国联通样本从 3 条增至 5 条；
- 加入云计算与容器技能，以及卫星通信与 TCP/IP 技能；
- 加入“算力运维”和“卫星网络运营”两个异名岗位，扩大网络、运维和解决方案查询的候选范围。

## 仍存在的偏差

- 15 条样本仍只覆盖三家通信运营商；
- 北京岗位占 6 条，地域分布不均；
- 石油石化、电网、粮储、铁塔和中车尚无满足纳入条件的单岗位 JD；
- Java 后端、前端、软件测试和数据开发岗位仍不足；
- 当前数据用于开发调试，不能作为冻结测试集或对外准确率证明。

## 下一批优先级

1. 优先补充 5 条非通信运营商岗位；
2. 若官方入口只能提供岗位专业大类，不把公告强行拆成单岗位 JD；
3. 补充 Java、测试和数据开发职责清晰的岗位；
4. 达到 20 条后冻结检索规则，再采集 10 条独立测试集。
