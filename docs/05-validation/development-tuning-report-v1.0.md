# 开发集检索调优报告 v1.0

## 方法

本轮只使用35条训练集建立同义词与IDF信息，并使用11条开发集选择方案。冻结测试集没有参与开发、调权或错误修复。

开发查询共12组：6组直接需求表达，6组避免复用JD原词的改写查询。比较以下方案：

1. OfferLab原始字段加权关键词；
2. 人工同义词增强；
3. 本地字符2–4 gram TF-IDF；
4. 同义词混合分与字符向量分的70/30、50/50和30/70融合。

所有方案均为本地运行，不调用付费API。

## 结果

| 方案 | Recall@5 | Recall@10 | NDCG@5 |
|---|---:|---:|---:|
| 原始字段混合 | 75.00% | 75.00% | 76.68% |
| 同义词增强 | 91.67% | 91.67% | 91.04% |
| 字符TF-IDF | **97.92%** | **100.00%** | 93.66% |
| 同义词/向量 70/30 | 95.83% | 100.00% | 95.06% |
| 同义词/向量 50/50 | 95.83% | 100.00% | **95.73%** |
| 同义词/向量 30/70 | 95.83% | 100.00% | **95.73%** |

原始6组查询过于接近JD措辞，四个主要方案几乎都达到满分；加入改写查询后，原始方案暴露出明显漏召回。典型失败包括“生成式AI/多Agent”“售前咨询/上线验收”“企业数据标准/元数据”等表达无法被原始精确匹配稳定覆盖。

## 冻结方案

- 第一阶段候选召回：字符TF-IDF，取Top 10；
- 第二阶段排序：同义词字段混合分50% + 字符TF-IDF 50%；
- 字段混合仍保持职责40%、技能35%、专业15%、标题10%；
- 展示理由继续从职责、技能和资格原文证据生成，不直接把向量相似度作为用户解释。

选择依据是岗位发现优先降低漏召回，因此使用字符TF-IDF做候选生成；融合方案用于排序和保留字段解释能力。

## 限制

- 开发集只有11条岗位，指标方差很大；
- 字符TF-IDF属于轻量文本向量，不代表真正的语义模型；
- 人工查询基于已知岗位族设计，可能高估真实流量表现；
- 当前57条语料尚未达到原定150条；
- 测试集只能在规则冻结后运行一次，测试失败只记录，不回头针对单条样本调参。
