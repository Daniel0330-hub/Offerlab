# 扩展开发集检索调优报告 v1.1

## 目标与边界

本轮使用35条训练集建立IDF和人工同义词，在19条、6家集团的开发集上比较方案。冻结测试集没有参与调参。开发集新增中国铁塔、中国电气装备、中国出版集团和中国银河金控，覆盖AIoT、系统运维、AIGC内容运营、用户分层、数字教材平台和行业研究等岗位族。

人工查询由12组增加到26组：13组直接表达和13组释义改写。相关性标签在运行前按职责证据确定；新增岗位导致旧查询相关集合发生变化时，按同一规则补标，而不是按排序结果删改标签。

## 结果

| 方案 | Recall@5 | Recall@10 | NDCG@5 |
|---|---:|---:|---:|
| 原始字段混合 | 75.00% | 78.85% | 75.13% |
| 同义词增强 | 88.46% | 93.27% | 86.11% |
| 字符TF-IDF | 92.63% | **100.00%** | 91.45% |
| 同义词/向量 70/30 | **96.15%** | 99.04% | 93.34% |
| 同义词/向量 50/50 | **96.15%** | 99.04% | 94.12% |
| 同义词/向量 30/70 | **96.15%** | 99.04% | **94.99%** |
| 字符Top10 → 30/70重排 | **96.15%** | **100.00%** | **94.99%** |

扩展后原始字段方案仍只有75%的Recall@5，说明仅依赖JD精确词会漏掉异名岗位。两阶段方案保留字符TF-IDF的Top10完整召回，同时用职责、技能、专业和标题的结构化字段改善前五名排序。

## 错误分析

- “AI应用、需求对接、方案落地”查询中，通用人工智能岗位会挤占具备明确需求和交付职责的岗位，说明通用AI词权重仍偏高；
- “生成式AI、知识库问答、多Agent”改写中，仅写RAG而未写智能体的岗位容易落到第六名，暴露跨概念语义能力不足；
- 系统运维与网络运维存在部分职责重叠，但数据库备份、企业内部系统和网络规划等证据能够帮助重排；
- 新媒体运营、私域会员、数字教材和行业研究等新增查询均能在Top5命中目标岗位，表明JD职责权重可以跨岗位名称工作。

## 冻结配置

- 候选召回：字符2–4 gram TF-IDF，Top 10；
- 重排：同义词字段混合30% + 字符TF-IDF 70%；
- 字段权重：职责40%、技能35%、专业15%、标题10%；
- 展示解释继续引用职责、技能和资格原文，不向用户展示不可解释的相似度分数。

配置保存在 `data/evaluation/retrieval-config-v1.1.json`。下一步是为冻结测试集单独建立查询与标签，完成一次最终测试；测试结果只报告，不再回头修改v1.1配置。
