# 画像—岗位JD匹配评测 v1.0

## 评测对象

- 产品候选语料：259条真实JD、18家集团；
- 开发画像：8个，覆盖数据分析、AI产品、开发、算法、数据开发、运维、安全和数字化运营；
- 冻结测试画像：4个；
- 每个画像同时包含专业、技能、项目证据、目标方向、学历和地点偏好。

相关性标签要求岗位同时满足人工指定岗位族和至少一个核心能力/职责信号。地点仅作偏好，不作为相关性的必要条件。

## 调参结果

开发集网格搜索后的画像权重为：

| 画像信号 | 权重 |
|---|---:|
| 目标方向 | 40% |
| 技能 | 30% |
| 项目经历 | 15% |
| 专业 | 10% |
| 地点偏好 | 5% |

主动搜索存在时，最终排序采用75%画像匹配和25%主动搜索意图。明确届次、学历或必需专业不符的岗位降权，并默认不进入画像预筛选结果。

## 指标

| 数据集 | Recall@10 | NDCG@10 | MRR@10 |
|---|---:|---:|---:|
| 开发集 | 43.75% | 45.96% | 65.63% |
| 冻结测试集 | 45.00% | 48.17% | 62.50% |

将画像从“统计/数据分析”修改为“计算机/Java开发”后，Top 10仅重合20%，通过画像敏感性阈值（不高于50%），说明画像变化会实质改变推荐结果。

## 结论与限制

系统已经具备画像驱动的动态推荐能力，但当前排序质量仍处于实验基线，不能把45%的Recall@10描述为成熟推荐模型。主要问题是画像相关性标签仍由岗位族与人工核心信号组合生成、语料只覆盖18家集团，以及部分JD的技能结构化不完整。下一轮需要让真实求职者对画像—岗位配对进行三级标注，再优化语义召回和资格判断。
