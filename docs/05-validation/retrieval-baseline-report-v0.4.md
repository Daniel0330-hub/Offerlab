# 检索基线报告 v0.4

## 数据与标签变化

- 开发集由15条增至20条；
- 新增5条中国中车岗位，覆盖软件测试、AI、大数据和工业数据分析；
- 查询由5组增至8组，增加软件测试、大数据、振动诊断三类场景；
- “经营分析、风险预警”没有把工业振动数据分析标为相关，体现同名岗位按JD职责区分。

## 平均 Recall@5

| 方法 | 15条/5组查询 | 20条/8组查询 |
|---|---:|---:|
| 仅标题 | 48.33% | 61.56% |
| 标题+技能 | 85.00% | 88.12% |
| OfferLab混合检索 | 96.67% | 90.31% |

查询集合已经变化，两列用于展示迭代过程，不应解释为同一测试集上的直接升降。

## 解释

1. Q05共有8个相关岗位，Recall@5理论上限为62.5%，混合检索已达到该上限；后续应同时观察NDCG或改用更大的K值；
2. Q01暴露职责词形和意图边界问题，混合检索把数据软件、IT开发排在部分人工相关岗位之前；
3. 新增的测试、大数据和工业诊断查询都能召回目标岗位，但单一相关样本仍不足以证明泛化；
4. 标题基线均值提高主要来自新增查询的标题与意图高度一致，不推翻“异名岗位需要JD检索”的产品判断；
5. 90.31%是开发集调试结果，不是产品准确率。

## 下一步实验

- 方案A：人工审核的职责与技能同义词；
- 方案B：职责和技能文本的语义向量召回；
- 对比当前混合检索、方案A和方案B在8组开发查询上的Recall@5、NDCG@5与错误类型；
- 选定方案后冻结规则，再在未参与调参的10条测试集上验证。
