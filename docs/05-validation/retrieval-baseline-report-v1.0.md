# 阶段性开发集检索基线 v1.0

## 数据与边界

- 开发集：11条岗位，来自中国移动和中国电科；
- 查询：6组人工查询，覆盖AI应用、大模型与智能体、网络运维、项目交付、工业视觉和数据治理；
- 评测时未使用冻结测试集；
- 开发集与训练集、测试集按`parent_group`完全隔离；
- 当前样本量较小，本结果用于验证方案方向，不作为最终泛化结论。

## 基线结果

| 方法 | Recall@5 | Recall@10 | NDCG@5 |
|---|---:|---:|---:|
| 仅岗位名称 | 48.61% | 48.61% | 60.53% |
| 岗位名称 + 技能 | 65.28% | 65.28% | 69.51% |
| OfferLab混合检索 | 100.00% | 100.00% | 98.38% |

混合检索沿用阶段3冻结的初始权重：职责40%、技能35%、专业/领域15%、岗位名称10%。结果支持“职责和技能应高于岗位名称”的产品判断。D02中AI研发工程师排在第三位，使混合方案NDCG@5未达到100%；该结果说明相关岗位虽然被完整召回，排序仍有改进空间。

## 风险与下一步

1. 6组查询由当前开发集人工构造，存在查询与样本措辞接近的风险；
2. 开发集只有11条，Recall@10区分度有限；
3. 当前是透明关键词覆盖基线，不是语义向量模型；
4. 下一轮在开发集比较人工同义词扩展和轻量语义向量，不查看冻结测试集；
5. 方案冻结后只运行一次11条测试集，并在报告中披露样本量限制。
