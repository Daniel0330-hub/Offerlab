# 三名真实用户推荐评测基线 v1.0

## 结果

|用户|画像重点|NDCG@10|Precision@10|高度相关数|
|---|---|---:|---:|---:|
|P1|统计/精算，数据分析、AI产品、经营分析|0.9259|0.80|7|
|P2|计算机，软件/算法/数据开发/运维|0.8673|1.00|7|
|P3|统计/应用数学，仅AI产品|0.9328|0.20|1|

宏平均NDCG@10为0.9087，Precision@10为0.6667，高度相关岗位平均5个。NDCG较高但不能掩盖P3只有20%的相关岗位：相关结果出现在较前位置，而候选集合仍混入大量开发岗位。

## 关键问题

1. **目标方向缺少组合约束**：AI产品被拆成AI信号后，计算机技能和AI关键词把软件、算法与数据工程岗位推入前10。修订后，当用户只选择AI产品且JD没有产品、需求、用户研究、解决方案或产品设计证据时降权。
2. **技能同义链不完整**：C语言、C++和JD中的C/C++未形成统一技能族。修订后显式识别C语言和C++，并与C/C++要求互通。
3. **地区没有约束候选集**：旧版地点仅占5%排序分。修订后画像填写地点时，“仅看画像预筛选”和推荐评测只保留相应地点；“查看全部岗位”仍用于主动扩展。
4. **原版JD入口过深**：旧版只能在证据抽屉底部打开来源。修订后每张岗位卡直接提供“查看原版JD”。
5. **无效画像字段**：删除语言能力输入；JD若明确要求语言，仍在基础资格中标记为人工确认，不用用户语言字段自动判断。

## 结论

首轮未达到Precision@10不低于70%的门槛，主要失败集中于单一“AI产品”方向。当前版本完成定向纠偏，但必须让P3或相似画像重新标注修订后的Top 10，才能报告改进幅度，不能用旧标签推算新版效果。

## P3第一次复测

P3使用统计/应用数学、北京、SQL/Python、仅AI产品画像重新标注。Precision@10由0.20上升至0.30，NDCG@10为0.8529，但高度相关岗位由1个降为0个，仍未通过阶段门槛。

复测暴露出第二层语义问题：规则把“AI产品”与“AI产品经理”的空格差异处理不足，同时把研发JD中的普通“产品”表述误当作产品管理证据。v1.2将同义表达补齐，并把产品职责证据收紧为产品经理、产品管理、产品规划、产品设计、产品全生命周期、需求分析/调研、用户研究或竞品分析。修改后浏览器验证“AI产品经理”已升至北京岗位首位，但北京语料中真正的AI产品岗位仍很少；下一轮要同时衡量排序错误和候选供给不足，第一次复测结果继续作为独立基线保留。
