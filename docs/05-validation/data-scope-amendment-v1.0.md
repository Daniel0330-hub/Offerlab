# 阶段5数据范围修订 v1.0

## 修订原因

此前把“20条开发集”同时当作岗位收集目标，混淆了岗位语料库和人工评测集。20条足以验证Schema与评测链路，却不足以支持跨央企、跨岗位族的稳定结论。

用户补充国务院国资委2026年7月11日发布的99家中央企业名录后，项目将企业来源从12家目标企业扩展为99家候选企业。

2026年10月6日，用户进一步指定名录序号1—20为优先采集范围。后续先覆盖这20家中的新集团；已经进入语料库的集团暂缓重复采集。该优先级只调整采集顺序，不降低来源、届次、单岗位边界和证据要求。

## 三层数据结构

### 1. 岗位语料库

凡满足以下条件的岗位均可进入，不设置20条上限：

1. 来自99家央企、所属单位官网或可确认归属的官方招聘系统；
2. 明确属于2027届校园招聘，或明确允许2027届投递；
3. 具有单岗位边界，或能从公告中可靠分隔岗位；
4. 至少包含职责、任职要求、专业或技能信息；
5. 保存来源URL、采集日期和原文；
6. 不使用搜索摘要代替完整JD。

目标规模为不少于150条岗位，覆盖不少于20家集团。语料库用于搜索、产品演示和后续抽样，不要求每条都完成人工金标准标注。

### 2. 训练集与开发集

- 训练集目标90条，开发集目标30条；
- 从岗位语料库分层抽样；
- 训练集用于技能归一、提示词示例、同义词和可选轻量排序实验；开发集用于方案选择、权重、阈值和错误分析；
- 每条完成人工结构化、证据核对和查询相关性标签；
- 单一集团原则上不超过开发集的15%；
- 当前20条与本轮新增岗位先作为已标注候选池，不删除、不提前固定拆分。

### 3. 冻结测试集

- 目标30条；
- 规则冻结后再抽取；
- 优先选择开发集中未覆盖的集团、岗位名称和职责表达；
- 不根据测试结果逐条修改同义词、权重或规则；
- 用于报告最终离线结果和失败案例。

## 抽样维度

开发集和测试集需要同时覆盖：

- 集团：能源电力、通信信息、装备制造、交通物流、建筑工程、资源材料、综合服务；
- 岗位族：产品、软件开发、算法、数据、大数据、测试、网络安全、云计算、运维、项目交付、数字化运营；
- 地点：北京和非北京，一线与非一线城市；
- 学历：本科、硕士以及学历未明确；
- 资格表达：必须、优先、至少一种、相关专业、信息缺失；
- 检索难例：异名高相关、同名低相关、跨行业技能迁移。

## 规模目标

| 数据层 | 目标 | 当前 | 用途 |
|---|---:|---:|---|
| 合格岗位语料库 | ≥150 | 57 | 搜索、演示、抽样池 |
| 人工训练集 | 90 | 35（阶段性） | 归一规则、示例和可选轻量训练 |
| 人工开发集 | 30 | 11（阶段性） | 方案选择和错误分析 |
| 冻结测试集 | 30 | 11（阶段性） | 最终独立验证 |
| 企业覆盖 | ≥20家集团 | 13家 | 降低来源偏差 |

## 时间和质量取舍

- 先扩大公开岗位语料，再从中做分层金标准；
- 通过脚本做格式检查，通过人工做证据和语义核验；
- 三周结束时如未达到目标，报告实际数量和缺口，不降低纳入标准、不复制岗位、不使用不可核验摘要；
- 数据扩展不改变MVP功能范围，只提高检索和评测可信度。
