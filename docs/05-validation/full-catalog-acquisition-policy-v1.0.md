# 候选岗位目录与评测语料分层规则 v1.0

## 为什么要拆分

此前原型直接使用 65 条人工核验语料展示岗位。它适合调试抽取、召回和排序，却不能代表企业的完整招聘范围，导致中国联通的产品经理、解决方案、数据与开发岗位大量漏收。

从 v1.0 起，项目维护两类互不替代的数据资产：

| 数据资产 | 用途 | 收录原则 | 是否允许限制单企数量 |
|---|---|---|---|
| 候选岗位目录 | 用户搜索、筛选和横向比较 | 对已接入企业的官方校招岗位做全量扫描，收录全部相关岗位 | 不允许 |
| 评测语料 | 抽取规则、召回排序调优与冻结测试 | 分层抽样、人工核验、版本冻结 | 允许，按实验设计确定 |

## 候选岗位目录准入规则

1. 来源必须能追溯到企业官方招聘站、企业官方合作招聘站或可核验公告。
2. 先完整获取企业在当前校招批次公开的全部岗位，再按岗位标题和 JD 证据分类。
3. 收录产品与解决方案、数据分析与治理、AI 与算法、软件与平台开发、运维/云/安全、测试与质量岗位。
4. “运营”“项目”“系统”等泛化词不能单独触发收录；需要明确的技术、产品或数据语境。
5. 每条岗位保留官方岗位编号、原始链接、采集日期、职责和要求原文证据。
6. 不因岗位名称陌生而排除；岗位名称仅用于第一层候选分类，最终匹配仍以 JD 职责、技能和资格为主。

## 覆盖审计

每家企业记录：官方公开总岗位数、相关岗位数、成功结构化数量、失败数量、最近同步时间和规则版本。目录中的岗位数量用于产品覆盖展示；评测集数量只用于说明实验规模。
