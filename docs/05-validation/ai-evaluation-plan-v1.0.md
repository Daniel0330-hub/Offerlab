# AI 离线评测计划 v1.0

> 历史版本：原计划为20条开发集与10条测试集。企业范围扩大后的当前计划见`ai-evaluation-plan-v1.1.md`。

## 评测对象

1. JD 字段提取；
2. 技能名称与要求级别提取；
3. 基础资格规则；
4. JD 驱动岗位召回；
5. 召回理由和比较摘要的证据一致性。

## 数据集设计

目标建立 30 条人工核验岗位：

- 12 家目标企业至少各 2 条；
- 产品、数据分析、经营分析、软件开发、算法、数据开发、测试、网络安全、数字化运营均有覆盖；
- 至少 6 条异名高相关正例；
- 至少 4 条同名或标题相近但职责低相关反例；
- 至少 6 条含 required/preferred/exposure 边界措辞；
- 至少 4 条关键信息缺失，应输出 unknown；
- 地点覆盖至少 6 个城市。

前 20 条作为开发集，后 10 条冻结为测试集。提示词和规则调优期间不得查看测试集结果后逐条修补。

## 人工金标准

每条岗位由人工标注：

- 招聘类型、届次、学历、专业、地点；
- 职责主题与原文证据；
- 技能、归一名称、要求级别和原文证据；
- 种子用户的基础资格状态和技能覆盖状态；
- 对 5 个代表性查询的相关/不相关标签；
- 应被召回但标题不同的正例说明。

存在分歧时保留争议字段为 `adjudication_required`，不强行制造确定答案。

## 指标与发布门槛

| 模块 | 指标 | v0.1 门槛 |
|---|---|---:|
| 字段提取 | 招聘类型/地点/学历 exact match | ≥ 90% |
| 技能抽取 | 技能 micro-F1 | ≥ 85% |
| 要求分级 | required/preferred macro-F1 | ≥ 80% |
| 证据 | evidence_span 可在原文定位 | 100% |
| 资格规则 | 硬条件误杀率 | ≤ 5% |
| 资格规则 | 硬条件误放率 | ≤ 10% |
| 检索 | Recall@5 | ≥ 80% |
| 检索 | 异名岗位 Recall@5 | ≥ 75% |
| 检索 | 标题误导率@5 | ≤ 20% |
| 解释 | 无依据断言率 | 0% |

小样本结果必须同时报告分子和分母。

## 对照实验

- Baseline A：只按岗位标题关键词；
- Baseline B：标题 + 技能关键词；
- OfferLab：职责 + 技能 + 专业/领域 + 标题混合检索。

重点不是证明综合分更高，而是证明 OfferLab 能多找出异名高相关岗位，同时抑制同名低相关岗位。

## 成本和延迟

每次评测记录：模型、调用次数、输入/输出 token、总成本、单条平均耗时、失败和重试次数。API 预算超过 50 元项目上限时停止调用，改用缓存结果。

## 阶段通过条件

- Schema、提示词和规则版本已冻结；
- 30 条金标准数据完成；
- 三种检索方案跑完相同查询；
- 错误按统一类型归档；
- 至少修复一个高频错误并重跑相关测试；
- 生成包含失败样本的评测报告。
