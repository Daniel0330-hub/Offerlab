# MVP 功能验收标准 v1.1

## AC-01 能力画像
**Given** 用户首次进入，**When** 输入毕业年份、学历、专业、地点、技能及证据，**Then** 系统保存并展示可编辑画像。

## AC-02 岗位搜索
**Given** 已有核验岗位样本，**When** 用户输入方向、技能、公司或地点，**Then** 系统返回符合基础筛选条件的岗位并显示搜索条件。

## AC-03 异名召回
**Given** 岗位名称与查询词不同但 JD 职责和技能高度相关，**When** 用户搜索，**Then** 该岗位可进入结果，不能因名称不同直接排除。

## AC-04 抑制标题误导
**Given** 岗位名称相似但职责和技能明显不相关，**When** 系统排序，**Then** 该岗位不能仅因名称相似进入高位。

## AC-05 解释召回
**Given** 岗位进入结果，**When** 用户查看卡片，**Then** 系统展示命中的职责或技能，且可回溯到 JD 原文。

## AC-06 基础资格
**Given** 用户画像和 JD 中有届次、学历、专业、地点条件，**When** 系统判断，**Then** 每项输出“满足/不满足/信息不足”和证据。

## AC-07 技能覆盖
**Given** JD 提及 Java、Python、SQL 等技能，**When** 系统解析，**Then** 展示技能、要求级别、用户证据和“已覆盖/缺口/信息不足”。

## AC-08 要求级别
**Given** JD 使用“熟练掌握”“优先”“了解”等措辞，**When** 系统判断，**Then** 不把优先项误判为硬性淘汰条件，并保留原文。

## AC-09 英语条件
**Given** 用户未录入英语证书，**When** 系统召回岗位，**Then** 英语不作为独立检索权重；若 JD 明确要求，则在“其他明确条件”展示，不能自动推断等价关系。

## AC-10 岗位详情
**Given** 用户点击岗位，**When** 详情打开，**Then** 用户能看到职责、技能、资格判断、风险、来源和原文证据。

## AC-11 横向比较
**Given** 用户选择 2–3 个岗位，**When** 进入比较页，**Then** 并列展示共同与独有职责、技能、资格风险、地点和志愿规则。

## AC-12 用户决定
**Given** 用户完成比较，**When** 选择加入志愿、备选或放弃，**Then** 保存决定和理由，不以系统分数覆盖用户选择。

## AC-13 低成本演示
**Given** 评审者获取仓库，**When** 按 README 运行，**Then** 无需付费 API、实时爬虫或账号即可完成主流程。
