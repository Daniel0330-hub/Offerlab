# 岗位召回与技能匹配策略 v1.0

## 目标

从小规模岗位库中发现与用户专业、技能和目标方向相关的岗位，包括职位名称不同但实际职责高度相关的机会。

## 两阶段流程

### 第一阶段：资格基础过滤

先处理不依赖职位语义的明确条件：

- 是否属于目标招聘类型；
- 届次；
- 学历；
- 专业明确排除；
- 地点硬偏好。

英语不作为独立过滤项。JD 中的语言要求进入“其他明确条件”。

### 第二阶段：JD 驱动召回与排序

对通过基础过滤或需要核实的岗位，根据以下信号计算“岗位相关性”，不计算录取概率：

| 信号 | 初始权重 | 说明 |
|---|---:|---|
| JD 职责主题相关性 | 40% | 用户目标方向、项目任务与岗位实际工作内容的语义关系 |
| 技能与软件工具覆盖 | 35% | Python、SQL、Java、Axure、XMind、数据分析、需求调研等 |
| 专业与业务领域相关性 | 15% | 统计、精算、数据、风险、运营、产品、能源等 |
| 职位名称相关性 | 10% | 仅作为辅助信号，不能单独排除岗位 |

权重是 MVP 待验证假设，可在阶段 5 评测中调整。

## 召回规则

1. 标题不匹配但职责与技能高度相关的岗位可以被召回；
2. 标题匹配但职责与用户方向低相关的岗位降低排序；
3. 明确基础资格不符合的岗位默认不进入推荐列表，但可在“已排除”中查看原因；
4. 资格待核实的岗位可以召回，但必须带醒目标记；
5. 每个召回岗位至少展示一个职责证据或技能证据；
6. 不允许仅用大模型生成“适合你”而没有原文引用。

## 技能要求分级

| JD 表述 | 类型 | 用户缺失时的处理 |
|---|---|---|
| 必须、熟练掌握、能够独立使用、具备 X 年经验 | required | 标记明确技能缺口；是否构成不符合由规则配置 |
| 掌握、熟悉 | expected | 降低技能覆盖状态，保留人工判断 |
| 优先、加分、有经验者优先 | preferred | 作为加分项，不判定无资格 |
| 了解、接触过 | exposure | 弱信号 |
| 未提及 | unknown | 不根据常识补充要求 |

## 用户技能证据

技能不是简单的 yes/no 标签，而是：

- 技能或软件名称；
- 熟练程度（自评）；
- 项目/课程/实习证据；
- 证据描述；
- 最近使用时间（可选）。

例如：

```json
{
  "skill": "Python",
  "level": "proficient",
  "evidence": "使用 pandas 和 scikit-learn 完成统计建模项目",
  "source": "硕士项目"
}
```

## 匹配输出

每个岗位输出四组信息：

1. 为什么被找到：职责、技能、专业或标题信号；
2. 已覆盖技能：JD 原文与用户证据；
3. 技能缺口：required、expected、preferred 分级；
4. 待核实条件：信息不足或表述模糊。

## 不输出

- 录取概率；
- 单一综合“适配百分比”；
- 没有证据的技能推断；
- 因岗位名称不同而直接排除；
- 因缺少优先项而直接判定不符合。

## MVP 实现建议

小规模数据下采用可解释混合方法：

1. 人工归一化技能和职责标签；
2. 关键词/同义词匹配形成可解释基线；
3. 可选使用 embedding 计算职责语义相似度；
4. 使用规则区分 required/expected/preferred；
5. 保存各子分数和证据，不只保存总排序。
