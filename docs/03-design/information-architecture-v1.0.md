# MVP 信息架构与导航 v1.0

> 历史版本：已由 `information-architecture-v1.1.md` 取代。

## 页面结构

```text
OfferLab
├── 1. 我的资格画像
├── 2. 候选岗位
│   └── 岗位详情 / 资格审计
└── 3. 志愿比较
```

Streamlit 第一版使用侧边栏导航。岗位详情可以使用列表展开区或同页详情面板，不新增复杂路由。

## 页面一：我的资格画像

### 目的

建立资格判断所需的最小用户信息。

### 内容

- 届次；
- 学历；
- 硕士专业；
- 本科专业；
- 英语成绩；
- 目标城市；
- 接受轮岗；
- 技能；
- 目标岗位族。

### 主要操作

- 编辑；
- 保存到当前本地会话；
- 使用预设种子画像；
- 进入候选岗位。

## 页面二：候选岗位

### 目的

从小规模岗位库中形成可核验的候选集合。

### 顶部筛选

- 集团；
- 地点；
- 岗位族；
- 资格状态。

### 岗位卡

- 集团/招聘单位；
- 原始岗位名称；
- 地点和截止时间；
- 资格总状态；
- 待核实数量；
- 召回原因摘要；
- 官方来源；
- 查看审计；
- 加入比较。

### 详情/审计区

- 资格总状态；
- 各条件状态；
- JD 证据；
- 用户证据；
- 职责主题；
- 已有能力与证据缺口；
- 数据质量和最后核验时间。

## 页面三：志愿比较

### 目的

在有限志愿场景中比较 2–3 个岗位并形成用户自己的决定。

### 内容

- 集团志愿规则提示；
- 横向比较矩阵；
- 所有不符合和待核实项置顶；
- 职责主题与用户证据；
- 截止时间、官方来源；
- 优先投递/备选/暂不投递；
- 选择理由；
- 志愿占用提示。

## 导航规则

1. 用户可直接使用默认画像进入岗位列表；
2. 加入比较至少 2 个、最多 3 个岗位；
3. 比较岗位可以跨集团，但志愿限制按集团分别计算；
4. 资格不符合的岗位仍可加入比较，界面不得隐藏用户选择；
5. 所有 AI 解释必须允许回到原文证据。
