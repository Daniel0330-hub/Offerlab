# 用户故事与 MoSCoW 优先级 v1.1

> 状态：阶段 3 当前基线。v1.0 已被本文件取代。

## Must Have

1. **能力画像**：录入专业、学历、毕业年份、地点、技能和项目证据。
2. **岗位搜索**：按公司、地点、岗位方向和技能搜索校招岗位。
3. **异名岗位召回**：阅读 JD 职责和技能，即使名称不同也能找到相关岗位。
4. **召回解释**：说明为何找到该岗位，包括命中的职责、技能和专业信息。
5. **基础资格判断**：对届次、学历、地点等输出“满足/不满足/信息不足”及原文证据。
6. **技能匹配判断**：区分必需、期望、优先和了解型技能，展示覆盖项、缺口与待确认项。
7. **岗位详情**：集中查看 JD 摘要、证据和风险，并决定是否加入比较。
8. **横向比较**：比较 2–3 个岗位的职责、技能、资格、地点和志愿代价。
9. **保留用户决定**：记录加入志愿、备选或放弃及理由，由用户最终决策。
10. **低成本演示**：使用本地样本完成流程，无需登录、付费 API 或实时爬虫。

## Should Have

- 按公司、地点、岗位族和技能组合筛选；
- 展示因硬性条件未满足而被排除的岗位及原因；
- 支持从搜索结果直接加入比较；
- 在比较页突出岗位独有技能；
- 保存一次决策的时间和理由。

## Could Have

- 用户调整检索权重；
- 相似岗位推荐；
- 投递结果回填和复盘；
- 导出比较报告。

## Won't Have in MVP

- 全网实时爬虫和持续自动更新；
- 自动投递或代填网申；
- 商业级账号系统和多端同步；
- 仅凭岗位名称推荐；
- 用单一综合分替代证据和用户判断。
