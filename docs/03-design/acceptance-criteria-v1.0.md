# MVP 功能验收标准 v1.0

> 历史版本：已由 `acceptance-criteria-v1.1.md` 取代。

## AC-01 用户画像

- Given 用户进入“我的资格画像”；
- When 使用默认种子画像或完成必填字段；
- Then 系统保存当前会话画像并允许进入岗位列表；
- And 缺失届次、学历、专业或目标地点时明确提示；
- And 不因缺失信息自动判为符合。

## AC-02 岗位列表与筛选

- Given 岗位样本已加载；
- When 用户按集团、地点、岗位族或资格状态筛选；
- Then 列表只显示符合组合条件的岗位；
- And 每张卡显示官方来源、核验时间和总体资格；
- And 截止时间未知时显示“待核实”。

## AC-03 资格逐项审计

- Given 用户打开一个岗位；
- When 系统展示资格判断；
- Then 招聘类型、届次、学历、专业、英语、地点分别显示状态；
- And 每个确定状态都有岗位原文证据；
- And 每个用户相关判断都有用户证据；
- And 模糊的“相关专业”不能自动判定为符合；
- And 明确 CET 要求不能由 TOEFL 自动替代。

## AC-04 总体资格

- Given 任一强制条件明确不符合；
- Then 总体状态为“不具备明确资格”；
- Given 没有不符合但存在待核实；
- Then 总体状态为“需要核实”；
- Given 所有适用强制条件均符合；
- Then 总体状态为“具备明确资格”。

## AC-05 相关性解释

- Given 岗位总体资格已经生成；
- Then 系统单独展示召回原因、已有证据和能力缺口；
- And 不显示录取概率；
- And 相关性说明不能覆盖硬性不符合。

## AC-06 加入比较

- Given 用户位于岗位列表或详情；
- When 加入第 1 个岗位；
- Then 提示至少再选择 1 个；
- When 加入第 2 或第 3 个岗位；
- Then 可以进入比较页；
- When 尝试加入第 4 个岗位；
- Then 提示先移除一个，不静默替换。

## AC-07 横向比较

- Given 已选择 2–3 个岗位；
- Then 所有不符合和待核实项优先展示；
- And 使用统一字段比较资格、职责、用户证据、截止时间和来源；
- And 原始岗位名称始终保留；
- And 缺失信息显示 unknown；
- And 系统不自动选出唯一最佳岗位。

## AC-08 集团志愿规则

- Given 岗位所属集团存在志愿上限；
- Then 比较页显示上限、当前选择数和规则来源；
- When 用户的优先投递数量超过上限；
- Then 显示冲突警告；
- And 保留用户选择供其调整；
- Given 志愿规则未知；
- Then 显示“规则待核实”，不得假设无限投递。

## AC-09 用户决定

- Given 用户完成比较；
- When 设置优先投递、备选或暂不投递；
- Then 系统保存当前会话决定与理由；
- And 用户可随时修改；
- And 系统不强制接受 AI 建议。

## AC-10 无 API 演示

- Given 未配置任何模型 API Key；
- When 按 README 启动应用；
- Then 默认画像、岗位列表、资格审计和比较流程全部可用；
- And 预计算结果明确标注为演示数据。

## AC-11 数据与隐私

- 仓库不包含录音、原始简历、联系方式或密钥；
- 每条岗位存在公开来源；
- 测试用户只使用 P1 等匿名编号；
- `work/` 和 `.env*` 被 Git 忽略。
