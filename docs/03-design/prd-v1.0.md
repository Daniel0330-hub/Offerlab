## 2. 背景

应届生申请央企校招时，需要在集团及下属单位的招聘系统中寻找岗位。岗位信息格式不一致，同名岗位职责不同，专业、学历、届次和英语条件需要逐条核验。部分集团还限制可投单位或岗位数量，等待反馈期间可能无法改投。因此用户不仅需要“找到相关岗位”，还需要在有限名额下做出有依据的选择。

现有产品已经广泛覆盖岗位聚合、AI 匹配、同义岗位扩展、收藏跟踪和自动网申。OfferLab MVP 聚焦一个更窄、可评测的任务：资格逐项举证与有限志愿比较。

## 3. 产品目标

### 3.1 用户目标

用户可以在少量可信岗位中：

1. 看清自己是否满足硬性申请条件；
2. 找到每项判断对应的 JD 原文；
3. 识别需要人工核实的信息；
4. 比较 2–3 个岗位的职责、门槛与机会成本；
5. 自己决定如何使用有限志愿。

### 3.2 项目目标

- 验证证据化资格审计是否提高用户理解和信任；
- 验证有限志愿比较是否帮助用户发现重要差异；
- 展示 AI 产品经理的需求、规则、评测和迭代能力。

### 3.3 非目标

- 全网岗位聚合或实时爬取；
- 自动网申；
- 简历改写和面试训练；
- 录取概率预测；
- 商业化账户、支付、消息推送；
- 薪资和工时社区数据库；
- 长期求职 CRM。

## 4. 目标用户与场景

### 4.1 种子用户

- 2027 届硕士；
- 硕士统计学，本科精算学；
- Python、SQL；
- 目标北京；
- 接受轮岗；
- TOEFL 100，无 CET-4/6；
- 目标三大运营商和三桶油。

### 4.2 核心场景

用户面对同一集团的 3 个候选岗位，但最多只能使用 2 个志愿。用户需要知道哪些岗位明确符合、哪些条件待核实，以及两个志愿应该如何分配。

## 5. 核心流程

1. 用户检查或修改资格画像；
2. 进入岗位候选列表；
3. 系统先显示总体资格状态，再显示相关性说明；
4. 用户查看单个岗位的逐项证据；
5. 用户选择 2–3 个岗位加入比较；
6. 比较页展示硬性条件、职责、证据、未知项和志愿规则；
7. 用户选择“优先投递”“备选”或“暂不投递”，并记录理由；
8. 系统更新剩余志愿提示。

## 6. 功能需求

### FR-01 用户资格画像

用户可以查看和编辑：

- 毕业届次；
- 学历层次；
- 硕士与本科专业；
- 英语成绩类型与分数；
- 目标城市；
- 是否接受轮岗；
- 技能；
- 目标岗位族。

必填字段缺失时，不执行总体资格判断，并提示补充。

### FR-02 岗位候选列表

每张岗位卡显示：

- 集团和招聘单位；
- 原始岗位名和归一化岗位族；
- 工作地点；
- 招聘项目/届次；
- 截止时间；
- 总体资格状态；
- 需要核实的条件数量；
- 官方来源和最后核验时间；
- 加入比较操作。

支持按集团、地点、岗位族和资格状态筛选。

### FR-03 资格审计

对以下条件分别判断：

- 招聘类型；
- 毕业届次；
- 学历；
- 专业；
- 英语；
- 地点；
- 其他明确硬性条件。

每项显示：状态、岗位证据、用户证据和解释。状态只能是：

- `符合`；
- `不符合`；
- `待核实`；
- `不适用`。

任一明确强制条件不符合时，总体状态为“不具备明确资格”；没有不符合但存在待核实时，总体状态为“需要核实”；其余为“具备明确资格”。

### FR-04 相关性说明

在资格审计之后展示：

- 召回该岗位的原因；
- 用户已有证据；
- 尚未证明的能力；
- 职责主题；
- 信息不确定项。

相关性不输出录取概率，也不覆盖硬性资格结果。

### FR-05 岗位比较

用户可以选择 2–3 个岗位，按以下字段比较：

- 集团与招聘单位；
- 岗位族与原始名称；
- 总体资格；
- 届次、学历、专业、英语和地点；
- 核心职责主题；
- 用户证据覆盖；
- 待核实事项；
- 截止时间；
- 官方来源；
- 集团志愿上限、当前占用和锁定规则；
- 用户个人偏好。

比较页面不自动宣布唯一最佳岗位。

### FR-06 志愿选择记录

用户可为比较中的岗位设置：

- 优先投递；
- 备选；
- 暂不投递。

用户可选择或填写理由。若优先投递数量超过集团上限，系统提示冲突但不删除用户选择。

### FR-07 来源与时效

所有岗位必须显示官方 URL 和最后核验时间。缺少官方来源的岗位不能进入正式演示数据；截止时间未知时显示“待核实”。

### FR-08 演示数据与无 API 模式

应用提供 20–30 条人工核验的脱敏岗位样本和预计算分析。没有 API Key 时仍可完成全部核心流程。

## 7. 状态和异常

| 情况 | 产品行为 |
|---|---|
| 用户信息缺失 | 标记相关条件待补充，不输出假阳性 |
| JD 没有专业要求 | 专业为待核实或不适用，取决于招聘原文 |
| “相关专业”边界不清 | 输出待核实并保留原文 |
| 明确要求 CET-6，用户无 CET | 输出不符合，不用 TOEFL 自动换算 |
| 截止时间未知 | 显示待核实，不猜测日期 |
| 官方链接失效 | 标记需要重新核验 |
| 志愿规则未知 | 显示未知，不假定无限投递 |
| 选择超过志愿上限 | 警告冲突，保留用户选择以便调整 |

## 8. 数据与隐私

- 演示数据来自公开招聘页面；
- 保存原始 JD 快照和来源；
- 不把受访者录音、原始简历或个人联系方式提交到 GitHub；
- GitHub 仅包含脱敏画像和公开岗位样本；
- API Key 通过环境变量配置并列入 `.gitignore`。

## 9. 产品指标

详见 `metrics-framework-v1.0.md`。MVP 主要衡量任务成功率、资格理解正确率、差异发现数、任务耗时和 AI 资格判断错误。

## 10. 发布条件

- 20 条以上岗位样本可用；
- 无 API 模式可跑完整流程；
- 核心页面没有阻断性错误；
- 资格判断均有证据；
- 3 名用户完成测试；
- 记录至少一次迭代；
- README、运行说明、限制和评测结果齐全。
