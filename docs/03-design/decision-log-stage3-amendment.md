# 阶段 3 产品决策修订记录

## 决策

将岗位发现重新纳入 MVP，并把差异化从“是否提供推荐”改为“依据什么召回和解释岗位”。

## 用户纠偏

横向比较必须先有候选岗位。同名岗位在不同公司可能要求不同，异名岗位也可能高度相关。JD 中的软件和技能要求比英语偏好更适合作为当前匹配依据。

## 版本变化

| 维度 | v1.0 | v1.1 |
|---|---|---|
| 主链路 | 资格画像 → 候选审计 → 比较 | 能力画像 → 岗位发现 → JD 匹配 → 比较 |
| 岗位名称 | 展示字段 | 低权重检索信号 |
| JD 职责 | 审计依据 | 主要召回依据，初始权重 40% |
| 软件/技能 | 辅助信息 | 主要召回及资格依据，初始权重 35% |
| 英语 | 画像中的资格信息 | 无独立检索权重；仅处理 JD 明示条件 |
| 搜索 | 不在核心范围 | 必要基础能力 |

## 设计原则

1. 先用基础条件排除明确不适用岗位，再做相关性排序；
2. 标题不能单独决定召回或排除；
3. 技能要求结合措辞分级，避免把“优先”当作“必须”；
4. 排序值用于组织信息，不代替证据和用户决定；
5. 初始权重是待验证假设，须通过反例集和用户测试修订。
