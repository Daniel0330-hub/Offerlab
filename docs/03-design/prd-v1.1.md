# OfferLab MVP 产品需求文档（PRD）v1.1

> v1.1 修订：将岗位搜索和 JD 驱动召回纳入核心 MVP；提高职责与技能权重；移除英语独立匹配维度。

## 1. 产品目标

帮助应届生先从岗位库中发现名称不同但职责、技能和专业高度相关的职位，再判断基础资格和技能覆盖，最终横向比较候选岗位。

## 2. 核心流程

```text
创建能力画像
    ↓
输入目标方向/技能/企业/地点
    ↓
基础资格过滤
    ↓
按 JD 职责和技能召回岗位
    ↓
查看“为什么找到”和技能覆盖
    ↓
选择 2–3 个岗位
    ↓
横向比较并决定志愿
```

## 3. 功能需求

### FR-01 用户能力画像

用户可编辑：届次、学历、硕士与本科专业、目标地点、轮岗偏好、目标方向、技能和软件工具。每项技能支持名称、程度和项目/课程/实习证据。

英语不作为必填字段或独立匹配信号。

### FR-02 岗位搜索

用户可输入：

- 目标岗位或方向；
- 技能/软件工具；
- 公司/集团；
- 地点。

系统搜索标题、JD 职责、技能要求、专业要求和业务领域。标题不匹配不能成为排除理由。

### FR-03 基础资格过滤

分别判断招聘类型、届次、学历、专业、地点和其他明确条件。英语证书要求若存在，归入“其他明确条件”，不作为召回权重。

### FR-04 JD 驱动岗位召回

岗位排序的初始权重为：职责主题 40%、技能工具 35%、专业领域 15%、职位名称 10%。系统保存每个子分数和对应证据。权重将在评测阶段调整。

### FR-05 技能覆盖判断

从 JD 提取软件、编程语言、产品工具、分析工具和业务能力，并区分 required、expected、preferred、exposure。结果显示：

- 已有明确证据；
- 用户自述但缺少项目证据；
- 明确缺失；
- 信息不足。

缺少 preferred 技能不能判定无资格。

### FR-06 搜索结果卡

每张卡显示：

- 集团、招聘单位和原始岗位名；
- 地点、招聘项目和截止时间；
- 基础资格状态；
- 为什么被召回；
- 关键匹配职责和技能；
- required 技能缺口数量；
- 待核实事项数量；
- 官方来源；
- 加入比较。

### FR-07 岗位详情

岗位详情分为：

1. 基础资格；
2. 职责相关性；
3. 技能与软件覆盖；
4. 缺口与待核实项；
5. 原始 JD 和官方来源。

### FR-08 横向比较

用户选择 2–3 个岗位，比较：

- 基础资格；
- 实际职责主题；
- required/expected/preferred 技能；
- 用户证据覆盖；
- 技能缺口；
- 地点、截止时间和单位；
- 集团志愿上限与锁定规则；
- 用户偏好和选择理由。

### FR-09 用户决定

用户可设置优先投递、备选或暂不投递，并记录理由。系统提示志愿冲突，不替用户做最终决定。

### FR-10 演示数据与无 API 模式

提供 20–30 条人工核验岗位和预计算的召回、技能提取、资格判断结果。无 API Key 时可以完成搜索、详情和比较全流程。

## 4. 搜索与排序边界

- 搜索结果是岗位相关性排序，不是录取概率；
- 明确不符合届次或学历的岗位默认进入“已排除”，用户仍可查看；
- 资格待核实的岗位可以推荐；
- 技能缺口需要展示，不能自动改写用户经历；
- 岗位名称权重不得超过职责与技能权重；
- 所有匹配解释必须指向 JD 原文或用户证据。

## 5. 页面结构

1. 我的能力画像；
2. 岗位发现与详情；
3. 岗位比较与志愿决定。

## 6. 非目标

全网实时抓取、自动网申、简历改写、面试训练、录取概率、账户系统、付费系统和生产部署均不进入 v0.1。

## 7. 发布条件

- 搜索能够召回至少一个“名称不同但职责相关”的人工正例；
- 标题相似但职责不相关的岗位不会仅因名称排在最前；
- 所有推荐岗位展示召回证据；
- 技能要求完成分级；
- 20 条以上岗位支持搜索、详情和比较；
- 无 API 模式可用；
- 3 名用户完成测试；
- 至少一次迭代有前后对比。
